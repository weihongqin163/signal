# Agora-Hex JSON 协议文档设计

## 目标

将 `docs/json_msg/` 中的 11 个 JSON 示例文件和 `sig-protocol.pdf` 整理为一份可供协议评审、开发接入和测试核对使用的正式协议草案。

最终交付物为 `docs/agora-hex-json-protocol.docx`。文档状态标记为“Draft / 待评审”，不修改或覆盖任何源材料。

## 信息来源与判定规则

1. `docs/json_msg/*.txt` 用于确认消息名称、JSON 层级、字段名称、字段数据类型和示例值。
2. `docs/json_msg/sig-protocol.pdf` 用于确认评审范围和待确定的业务问题。
3. 仓库内已有代码和说明文档仅用于交叉检查名称、拼写及结构一致性，不作为新增协议约束的依据。
4. JSON 文件中的 UUID、地址、码率、分辨率、媒体 ID、会议号和名称均视为示例值；除非源材料明确说明，否则不推导枚举、范围、长度、单位或格式约束。
5. 无法从源材料确认的消息方向、触发条件、应答关系、字段必填性、单位、错误码和状态转换，均明确标记为“待确定”，不以经验补写。

## 文档结构

### 1. 文档控制

包含文档名称、版本、状态、编制日期、适用范围、依据文件和修订记录。

### 2. 协议概述

说明该协议采用单消息 JSON 信封：顶层对象仅承载一个消息名称，消息体为对应对象。对传输承载、字符编码和帧格式，仅记录源材料能够确认的内容；其余内容列入待确定事项。

### 3. 消息总览

汇总以下 11 类消息：

- `AgoraDialInIndication`
- `AgoraStartContentIndication`
- `AVCDialInRequest`
- `AVCDialInReply`
- `AVCNameChangedIndication`
- `AVCStartContentRequest`
- `AVCStartContentReplay`
- `DTMFIndication`
- `HangupIndication`
- `MutedIndication`
- `StopContentIndication`

总览表包含消息名称、用途、方向、关联消息和状态。无法仅凭目录内材料确定的单元格使用“待确定”，并在待确定事项章节建立对应条目。

### 4. 公共数据结构

按 JSON 路径归纳可复用结构，包括：

- `callId`
- Agora 端点显示信息
- AVC 信令端点
- 音频媒体属性
- 视频/内容媒体属性
- 最大分辨率

字段表包含字段路径、JSON 类型、样例值、说明和约束状态。必填性不根据字段在单个示例中出现就直接推定为协议强制要求。

### 5. 消息定义

每类消息采用统一模板：用途、方向、触发条件、关联消息、字段定义、完整 JSON 示例、处理说明及待确定内容。JSON 示例保留源文件结构并使用等宽字体展示。

### 6. 关联与交互规则

归纳 `callId` 在消息间的关联用途，以及拨号、挂断、静音、名称变化、双流开始/停止和 DTMF 等消息的潜在交互关系。仅把材料明确支持的关系写为规则；其余内容使用评审问题表达。

### 7. 待确定事项

保留并整理 PDF 中的未定内容：

- 会议不存在时采用的消息及行为
- 用户上线、下线、被踢出或不允许加入时的通知机制
- 用户媒体状态变化的消息定义
- RTC 侧屏幕共享时的协议行为
- 会议不存在时的 IVR 播放要求
- 单流会场、等待位、固定提示信息及多终端场景下的媒体选择
- 单会场或多会场场景下与 SIP、Agora 端和 active speaker 的关系
- 设备硬件关闭摄像头时的状态通知
- 各消息的方向、可靠应答和超时/重试规则
- 字段必填性、取值范围、长度、单位、枚举和兼容性规则
- `DTMFIndication.event` 的完整取值集合及方向
- `AVCStartContentReplay` 名称中的 `Replay` 是否为最终协议拼写

每个事项包含问题描述、影响范围和建议确认结论栏，便于后续评审补录。

### 8. 附录

提供消息与源文件对照表、术语缩写表及示例值免责声明。

## 排版设计

采用正式技术规范样式：A4 纵向、清晰的三级标题、页眉显示协议简称和草案状态、页脚显示页码。主色使用克制的深蓝灰，确认内容与待确定内容通过文本标签和浅色提示框区分。

字段表按内容分配列宽，长字段路径和说明允许自动换行，不设置可能截断文字的固定行高。较长 JSON 示例使用单栏代码块，避免塞入窄表格。跨页表格重复表头，并通过分页控制避免标题与正文分离。

## 验收标准

1. 11 个 TXT 文件均在消息总览、详细定义和源文件对照表中出现。
2. 每个源 JSON 字段至少在公共结构或对应消息字段表中出现一次。
3. PDF 中可识别的未定业务问题全部进入“待确定事项”。
4. 文档不包含未经材料支持的强制性方向、枚举、范围、单位或业务状态转换。
5. 文档中无占位符、内部工具信息或生成过程说明。
6. DOCX 能成功渲染为逐页 PNG，且所有页面无文字截断、对象重叠、破损表格和异常分页。
